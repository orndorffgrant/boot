# Dependency source offer

`boot` uses a two-level source offer.

1. **First-party source** is embedded in the binary and served at
   `GET /v1/source`. It contains this repository, `Cargo.lock`, and the build
   instructions.
2. **Dependency source** is published as a release asset and offered at
   `GET /v1/source/dependencies`. It contains the normal and build dependency
   graph for the Linux release targets, compressed with xz.

The dependency bundle is generated by:

```bash
tools/dependency-source.sh \
  --output target/source/boot-<version>-dependencies.tar.xz
```

It contains:

- `vendor/` — the complete crate source;
- `DEPENDENCY-SOURCES.json` — exact versions, license expressions, checksums,
  upstream URLs, and vendor paths;
- `THIRD_PARTY_NOTICES.md` — package-level notices;
- `Cargo.lock`, `LICENSE`, and `NOTICE`.

The server exposes:

- `GET /v1/source` — first-party source tar;
- `GET /v1/source/dependencies` — redirect to the dependency bundle;
- `GET /v1/source/manifest` — JSON description of the dependency bundle.

These endpoints are public and must not be placed behind an auth proxy.
See [docs/licensing.md](docs/licensing.md).
